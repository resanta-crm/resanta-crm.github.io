# GPS: устойчивость ИИ и быстрые переходы — 21.10.2026

## Зафиксированные ошибки и причины
- 21.10 около 16:11 по Минску запрос `crm-gps-stop-ai-v1` завершился `AI_EMPTY`: модель вернула ответ без ожидаемого текста (предыдущий лимит 900 output tokens).
- 21.10 около 16:09–16:10 `crm-gps-meeting-ai-v236441` совершил две последовательные попытки по 30 сек., обе прервались с `AbortError`; браузер ждал 47 сек. и мог прервать процесс ещё до серверного завершения.
- Видео пользователя показало длинную страницу GPS, таблицу на десятки дней и отсутствие удобного перехода к ИИ-повестке.

## Исправления
- Разбор остановки: модель `gpt-5-mini`, `reasoning.effort=low`, лимит выходных токенов 2400, сетевой тайм-аут 25 сек. При неполном/пустом ответе — краткий **резерв по правилам CRM** с явной маркировкой. Резерв нельзя представлять как текст модели; подтверждённые и неизвестные факты разграничены.
- Повестка: одна попытка `gpt-5-mini` с `effort=low`, тайм-аут 24 сек. и лимит 3000 токенов. Входной список ограничен 16 спорными примерами и 5 рекомендациями в ответе. Если модель недоступна — максимум 5 **фактических** проблем со ссылками на маршрутные записи. Резервный ответ не попадает в ИИ-кэш, т.к. не является генерацией модели. Исключено двухкратное ожидание по 30 сек.
- UI: компактная повестка, фильтры по адресатам, раскрытие подробностей по нажатию на вопрос, кнопки «Открыть разбор ТТ» (передаёт id существующему модальному доказательству) и «К GPS-остановкам». Раздел GPS-руководителя имеет закреплённые переходы: Сводка / ИИ-повестка / Время / Спорные ТТ.
- Длинный список GPS-дней показывает сначала шесть строк, остальные по нажатию. Отображаемый результат резервного разбора остановки явно помечен как работа правил CRM.
- Сбои ИИ не пишут в таблицы визитов, маршрутов, GPS-точек или решения ДФ. Нет фоновых платных запросов.

## Проверки
- Корневые причины `AI_EMPTY` и двух `AbortError` проверены по журналам Supabase.
- Обе Edge Functions развёрнуты активными с JWT-проверкой.
- Код UI проверен через компиляцию JS, версия ассетов увеличена до `23.7.9`.
- Ранее проверена защищённость кэша ИИ от `anon` и прямого чтения `authenticated`.
- **Ещё требуется:** тест первого ответа модели и раскрытия вопросов в живом браузере под учётной записью директора. Обычная проверка кода его не заменяет.

## Порядок ручного приёмочного теста
1. `GPS-контроль → Руководитель`: переходы «Сводка», «ИИ-повестка», «Время», «Спорные ТТ».
2. Нажать «Подготовить совещание». Ожидается ответ модели или помеченный резерв CRM, без голого `AbortError`.
3. В повестке выбрать тип вопросов, развернуть карточку, открыть доказательства по ТТ, вернуться к GPS-времени.
4. В контроле времени 01–20 октября / 60 минут проверить скрытие дополнительных дней, раскрытие по кнопке; Руднев 20.10 / 99,2 мин / «ИИ-разбор».
5. Убедиться, что при отказе модели показываются факты и ограничение достоверности, а не утверждение о виновности менеджера.
