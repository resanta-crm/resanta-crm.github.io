# РЕСАНТА AI 360° — быстрые голосовые поручения, 26.10.2026

## Цель

Сократить заметную задержку после голосовой команды и по возможности приблизить ответ к пяти секундам без потери точности и проверок доступа. **Пять секунд — ориентир, не гарантированный предел**: на результат влияет STT, сеть и SQL. Измеренные около 2,67 с относятся только к существующему SQL-снимку для Руднева, не ко всему пути «голос → ответ».

## Безопасные изменения

1. `assets/135-resanta-voice-capture-fix-v2.js`: ручной вопрос ограничен пятью секундами вместо десяти; постоянный режим остаётся до девяти секунд для длинной речи. Повторное нажатие ручного микрофона при уже включённом постоянном режиме не останавливает его. Подсказки различают два режима.
2. `assets/140-resanta-ai360-task-drafts-preview-v1.js`: один вызов `kind:'preview_query'` вместо последовательных `directory` + `preview`, проверка фамилии и данных на сервере. Интерфейс не создаёт задачи. В статусе доступна продолжительность проверки на клиенте.
3. `supabase/functions/crm-ai360-task-drafts-v1/index.ts`: сохранены JWT, конкретный директор, принадлежность менеджера филиалу, однозначное закрепление клиентов и исключение существующих задач/маршрутов. Новый однозапросный режим `preview_query`, старый `preview` оставлен для обратной совместимости. Проверки задач и маршрутов читаются параллельно. Конкретные поручения выбираются по фактам: давно не посещался, резкое снижение связанных закупок, следующий заказ. При наличии разных сценариев выборка стремится не дублировать тип поручений. Ни SKU, ни план закупок, ни причина снижения не выдумываются.
4. Ограничение частоты запросов к новому endpoint — один запрос в четыре секунды, только авторизованный директор. Нет фонового опроса.
5. Обновлены версии кэшируемых скриптов (загрузчик `v16`, голос `v13`, черновики `v2`). Android/WebView и загрузка на входе не затронуты.

## Проверки

- Все пять файловых/VM-тестов `ai360-panel-ux-v1`, `ai360-remembered-wake-session`, `ai360-task-drafts-readonly-v1`, `ai360-voice-video-regression-20261026`, `ai360-fast-voice-proposals-20261026` прошли. Это НЕ реальные E2E-измерения скорости браузера и не заменяет независимые GitHub CI тесты.
- Edge Function развёрнута в Supabase отдельно, `verify_jwt=true`, только чтение, старый клиентский `kind:'preview'` продолжает поддерживаться.
- Ни одна запись в `public.tasks` не создаётся. Схема и RLS не меняются. Другие Edge Function не изменены.

## Проверить после обновления

Открыть директорский resanta-crm.by, Ctrl+F5, включить голосовой режим. Один раз произнести «Лера, предложи три поручения для Руднева» и замерить фактическое время от конца речи до появления текста черновиков. Повторить с Ачинович и Шкуран (учесть один запрос в четыре секунды). Нажать ручной микрофон при включённом постоянном режиме: он не должен переключаться/выключаться. Проверить разовую команду (максимум пять секунд) отдельно. Убедиться, что варианты поручений основаны на цифрах CRM и сохраняются только как черновики.

## Откат

При ухудшении поведения фронтенда вернуть предыдущие версии `135`, `137`, `140` и `index.html` из main до выпуска. При ошибке новой серверной функции — восстановить `crm-ai360-task-drafts-v1` по предыдущей версии исходника (версия 2, из коммита до этого PR), с `verify_jwt=true`. Это вернёт старые двойные запросы, поэтому откатывать сервер и клиент вместе. Никаких таблиц и данных не откатывать: они не менялись.
