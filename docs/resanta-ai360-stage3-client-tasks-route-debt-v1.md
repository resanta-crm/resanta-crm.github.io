# РЕСАНТА AI 360° — этап 3, аналитика клиентов и работы менеджеров
Дата: 22.10.2026

## Статус
- Сервер: Supabase Edge Function `crm-ai360-director-v1`, версия 5, JWT + подтверждённая запись директора.
- Новый серверный read-only RPC: `crm_ai360_operations_snapshot_v1(p_manager,p_month)`. `SECURITY INVOKER` (по умолчанию), доступ на вызов только `service_role`, `anon` и `authenticated` запрещены.
- Использует **существующий** `crm_ai360_sales_kpi_snapshot_v1`, не дублирует импорт продаж.
- Фронтенд: `assets/138-resanta-ai360-sales-bridge-v1.js?v=4`, подключается только вручную после нажатия директора, вне Android.
- Все данные только для чтения. Никаких UPDATE/INSERT/DELETE задач, клиентов, долгов, GPS и маршрутов. Поручения — только текстовый черновик на согласование.

## Источники
1. `clients`: текущие неархивные, неудалённые клиентские карточки, закрепление за менеджером на СЕГОДНЯ.
2. `purchase_history`: связь с клиентами **только** по `client_id`. Для снижения сравниваются два завершённых месяца (последний закрытый и тот же месяц прошлого года). Текущий месяц учитывается лишь как предварительный. Часть продаж без корректного `client_id` не распределяется искусственно.
3. `tasks`: открытые, просроченные по `due_date`; по `manager_name`, а для примеров клиентов по `client_id`.
4. `visits`: только не помеченные дублями, с `date <= сегодня`; визит НЕ доказывает достоверность GPS.
5. `route_plans`: не удалённые планы посещений на ближайшие 30 дней; не считать план посещением.
6. `client_debt`: актуальный отчетный день; фамилия менеджера из первого слова ФИО. Сумма и сроки задолженности, отчётные пороги 30/60 дней. Не утверждать полную доказанность `client_id`.
7. `manager_kpi_plans` и `crm_import_status`: план менеджера и свежесть импорта.

## Проверено 22.10.2026
- Для Руднева: 274 активных клиентов, 28 с отрицательной динамикой последнего закрытого месяца к соответствующему периоду год назад, 249 незавершённых задач, 178 просроченных, 75 не удалённых маршрутов на следующие 30 дней, задолженность 42 548,10 BYN (21 строка отчета). Эти цифры не следует выдавать за полные факты по всей сети и необходимо перепроверять свежесть при новых вопросах.
- Для Ачинович и всей клиентской базы RPC вернул корректные ограниченные JSON.
- `anon` / `authenticated` не могут вызвать новый RPC напрямую; `service_role` может.
- Автоматические тесты `tests/ai360-manager-voice-dialogue.test.cjs`: одиночный менеджер, смена менеджера, контекст между уточняющими репликами, запросы клиентов/долгов/маршрутов/задач, черновики поручений.
- Живой результат модели в авторизованном браузере директора пока НЕ подтверждён.

## Границы
- Нет точных дневных продаж (помесячный импорт), нет исторического переназначения клиентов.
- Примеры в ответе: до 8 падающих клиентов, 8 должников и 6 просроченных задач; это приоритетная выборка, не полный список.
- Отрицательная выручка может возникнуть из-за возвратов/корректировок; причина требует документов.
- Нет автоматического создания задач. Редактор поручений с отдельным подтверждением — будущий шаг.
- Android, GPS-правила, авторизация и рабочие таблицы CRM не изменены.
