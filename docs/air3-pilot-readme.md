# РЕСАНТА AI · INMO AIR3 (изолированный пилот)

## Статус
Черновик в ветке `feature/air3-temporary-pairing-v1`. Основная CRM, работающие мобильные APK и её Android-ограничители не изменены. **НЕ включать в production без проверки на реальных очках.**

## Изоляция
- `air3-control.html`: страница на MacBook/телефоне, использует **существующий** Supabase Auth в том же браузере; пароль не отправляет в очки. Вход разрешён исключительно профилю `boss` — `Александр Паюшин` по серверному `public.users`.
- `air3.html`: браузер на INMO AIR3, ввод шестизначного кода, ожидание подтверждения. Нет Supabase JWT, refresh token, user password, localStorage/sessionStorage, service role.
- `crm-ai360-air3-gateway-v1`: отдельная Edge Function. Все команды управляются сервером, защищены от повторного использования. `verify_jwt = false` **только потому, что очки не имеют JWT**; защищённые команды дополнительно проверяют Supabase Auth пользователя, а доступ очков — хеш случайного токена, TTL и отзыв.
- Новый SQL: три таблицы с включённым RLS и закрытыми правами anon/authenticated, атомарный лимит обращений. Не меняются существующие таблицы/права/обработчики CRM.

## Протокол
1. На телефоне/MacBook: `air3-control.html` → «Подключить очки» → «Создать код» (2 мин).
2. На очках: `air3.html` → код. Сервер фиксирует пару и генерирует **ожидающее** подтверждение. Никаких данных и пользовательских токенов не отдаёт.
3. На телефоне: «Разрешить вход».
4. Очки получают случайный токен только после `redeem`; он хранится только в памяти открытой страницы. Токен хешируется на сервере; абсолютный TTL 30 мин, 10 мин без действий. Нет refresh токена.
5. Выход на очках: `close` отзывает токен сервера. Телефон: «Отключить» блокирует всё мгновенно. Информация очищается из UI.
6. Пилот Леры: read-only отчёты по продажам и ПДЗ через проверенные RPC; браузерное распознавание речи/синтез — только при наличии поддержки на INMO AIR3.

## Что НЕ готово / не разрешено
- Нет полной разговорной Леры AI360 / OpenAI STT + Яндекс TTS. Существующие защищённые функции требуют обычный user-JWT и не подходят для прямого вызова с общего устройства.
- Фраза пробуждения «Привет, Ресанта» без нажатия кнопки зависит от среды AIR3/Android, не реализована.
- Поручения, изменения в CRM и трансляция на экран не подключены. Только чтение двух проверенных отчётов.
- Нет подтверждения физической совместимости с браузером очков; нужен реальный тест.
- Нет развёрнутой БД, Edge Function и веб-страниц в production; компоненты в отдельной ветке.

## Порядок выпуска
1. Проверить TypeScript Edge Function локально и выполнить SQL в тестовой Supabase ветке (после согласования её стоимости).
2. Проверить RLS: anon/authenticated не видят ни пар, ни токенов, не вызывают лимитер напрямую.
3. Сценарии: неверный/просроченный/повторный код, повторное redeem, пара без подтверждения, чужой JWT, смена роли, выход в очках, отзыв с телефона, 10 мин бездействия, 30 мин от создания.
4. Сценарий гонки: одновременно revoke и redeem / ask — закрытый сеанс не отдаёт новые отчёты.
5. Нагрузочные пробы rate limit; CORS только разрешённые источники.
6. Проверить на AIR3: Chrome/Browser, ввод кода, микрофон, RU SpeechRecognition и RU TTS, безопасное закрытие вкладки.
7. Только затем опубликовать аддитивные компоненты, не меняя `index.html`, голосовые Android-гейты или APK.
