# ЛПР и дни рождения v2 · 14 ноября 2026

## Согласованная граница

Единый Витебск. Триовист — клиент категории VIP-ДД в разделе ЛПР, без отдельного направления и без создания финансовой карточки. Сохраняются VIP-ДФС/ДФ, МПП исчезает только из VIP-разреза ЛПР. Люди и даты МПП не удаляются; заполненные ЛПР продолжают учитываться как обычные. Глобальный VIP-реестр, клиенты, бюджеты, продажи, маршруты, GPS и финансовые формулы не переписываются.

Разрешены семь неизменяемых учётных записей: Александр, Сидарович, Ачинович, Руднев, Шкуран, Кришталь, Александренко. Сервер сверяет JWT через auth.getUser, подтверждение email, соответствие профиля и immutable ID. Менеджеры видят свою область, а два менеджера Триовиста — только персонально закреплённых ЛПР. Директора работают с согласованной областью Витебска. Принадлежность финансовых клиентов филиалу проверяется отдельно; назначение Триовиста хранится только у ЛПР.

## Интерфейс

Один прежний пункт «ЛПР и дни рождения». Вкладки: ближайшие даты, все ЛПР, что заполнить, Telegram. Поиск, три VIP-категории, менеджер для руководителей, периоды и страницы по 25. График показывает известные даты по месяцам. В форме есть поиск клиента, известный контакт из исходной карточки как подсказка, ФИО, должность, день/месяц, заметка и ответственное лицо для Триовиста. Год не запрашивается, неизвестные значения не создаются автоматически.

При редактировании клиент заблокирован, заметка сохраняется; архивирование требует подтверждения. Данные и незавершённое редактирование не переносятся между учётными записями. Ответы прежней сессии игнорируются, чтения и записи ограничены временем ожидания. Возврат из Telegram обновляет статус, если пользователь не редактирует форму.

Подтверждённые юридические группы используются только для представления и учёта покрытия: пять ТТ с одним ЛПР не показываются как пять незаполненных клиентов. Повтор того же имени и даты в другой доступной ТТ уже подтверждённой группы отклоняется. Похожие названия без подтверждённой связи автоматически не объединяются.

Две непривязанные VIP-записи можно явно сопоставить существующей карточке только для ЛПР, после проверки реквизитов. Для этого используется отдельная служебная таблица; глобальная VIP-классификация и финансовый client_id не меняются.

## Лера

Читает тот же разрешённый источник и отвечает про сегодня/завтра/неделю/месяц, именованный месяц, конкретного клиента/человека, заполнение и доставку. Даты известного клиента ищутся во всём справочнике, а не только в ближайших 14 днях. Staff-диалог передаёт именно вопросы ЛПР этому обработчику раньше общего агента; другие вопросы и действия сохраняют прежний маршрут. Старые ответы не перебивают новый вопрос. Модель и голосовые провайдеры не меняются.

## Telegram

За один день и в сам день рождения, начало в 10:00 по Москве/Минску. Получатели: текущий закреплённый менеджер и два согласованных руководителя. Для Триовиста — один ответственный, Кришталь или Александренко, плюс руководители. Это не рассылка всем менеджерам одновременно. Учитываются все заполненные действующие ЛПР, VIP — категория/приоритет, а не скрытая блокировка отправки.

Сервис сам проверяет пользовательские JWT и отдельный защищённый dispatch-secret для cron. Платформенный verify_jwt выключен именно у этого сервиса, поскольку он блокировал служебные запросы без Authorization ещё до проверки dispatch-secret. Обычный пользователь без действительного JWT получает 401, неверный dispatch-secret — 403. Секрет не передаётся браузеру; сравнение использует хеши и цикл постоянной длины. Права прямого чтения таблиц клиентским ролям не выдаются. Другие Edge Functions не меняются.

Перед отправкой событие атомарно захватывается в БД. При захвате повторно проверяются действующая запись, дата, закрепление и актуальный профиль. Уникальный ключ защищает от двух запусков. Известный отказ допускает до трёх попыток, неизвестный результат не пересылается вслепую. Нет привязки — отдельный статус без расходования попыток; после подключения можно обработать текущее событие. Незавершённая старая отправка помечается как неопределённая.

Расписание самого ЛПР-задания — каждые пять минут с 10:00 до 23:55, чтобы обрабатывать очередь, безопасные повторы и новые подключения. До 10:00 отправки нет. По шесть отправок на вызов, остальные подхватит следующий запуск. Для 29 февраля в невисокосный год — 28 февраля с явной пометкой. Старые записи «за три дня» не удаляются из истории, но новые такие события не создаются.

Проверка dry_run читает данные, статусы семи профилей и при необходимости вызывает Telegram getMe. Она не создаёт отправок и не пишет личные данные. Проверка бота не означает, что сотрудники прочитали сообщения.

## APK

Прямой и дополнительный загрузчики получают одну версию модуля ЛПР. Проверены все семь профилей в DOM с native Android-контекстом и существующие сценарии APK. Сервис принимает явные адреса встроенного Capacitor-браузера, сохраняя серверную авторизацию. Стандартные hostname/scheme сверены с [документацией Capacitor](https://capacitorjs.com/docs/config).

ADB не обнаружил подключённых устройств; установленный APK вручную не проверен. Если APK загружает рабочую CRM с сайта, обновление интерфейса приходит при обновлении/перезапуске CRM. Для APK со встроенным старым набором файлов может потребоваться новая сборка — исходники установленного пакета в этом репозитории отсутствуют. Серверные данные и Telegram-обработка общие для обеих оболочек.

Кришталь и Александренко должны лично открыть «Подключение» и подтвердить привязку своего Telegram. Администратор не может безопасно подключить чужой Telegram вместо владельца. Имеющиеся пять привязок сохранены.
