# CONNECT v2 — screen viewing, scoped push and call lifecycle

Camera tracks previously shared a small tile with screen share, making CRM text unreadable. Screen tracks now occupy a separate main stage, with camera thumbnails, selection between multiple shares, fit/100%/150% views, browser fullscreen with a supported-platform error, and an explicit audio-unlock control. Calls still use the existing LiveKit identity, membership and video entitlement.

Chat updates preserve scroll position and load earlier history. Per-room drafts survive navigation, late send results cannot clear text in another chat, and read acknowledgements require the matching visible, focused chat at the bottom, bounded by the displayed message ID. Read receipts use member last_read_at. A narrow display uses one list or one conversation.

New calls use server-generated call IDs and start/accept/decline/leave/end states, a 90-second invitation and missed-call state. Concurrent starts reuse one active call. Plain-text prefixes no longer create incoming calls. Old messages remain unchanged.

Every newly saved text/media/call invitation atomically queues notifications. The separate CONNECT worker sends Web Push and existing Android FCM, validates current recipient/device ownership, membership, video rights and mute settings, uses bounded claims/retries and records uncertain delivery without blind resends. Provider acceptance is explicitly distinct from a human-confirmed self-test. The legacy sender endpoint now acknowledges the server queue without sending a duplicate.

Browser enrollment is explicit per browser/profile. The push worker has no fetch handler or CRM cache interception. Only configured HTTPS push-provider endpoints and valid encryption keys are accepted. VAPID private key, subscriptions, tokens and dispatcher secret are service-only. Authenticated browser actions verify the Supabase user; worker actions independently verify a protected dispatcher secret. Anonymous routes cannot read data or dispatch. Registration follows the current account; logout disables the browser binding and unsubscribes. Native registrations resume only when permission was already granted.

Supabase changes are confined to CONNECT tables/functions, with an attachment-room correlation fix and four FK indexes. No clients, routes, budgets, sales, LPR or AI-agent logic changes. Existing chat/video permissions and room IDs remain. No old messages are queued.

## Deployment and rollback

Apply the three timestamped CONNECT migrations, deploy `connect-delivery-v2` (internal JWT/dispatcher authentication, verify_jwt=false), `connect-fcm-send` compatibility endpoint and native-origin addition in `connect-livekit-token`. The minute cron backs up immediate pg_net dispatch from the message trigger. Publish the versioned browser assets and `/connect-push-sw.js`.

For a rollback disable only the `connect-delivery-v2` cron and the `connect_message_queue_v2` trigger, restore CONNECT frontend and previous sender function. Keep the additive tables/history for recovery; do not delete messages or unrelated data. The new migration functions retain existing membership checks.

## Operational limits

Each browser needs its own subscription. A closed browser process, sleeping PC, Do Not Disturb, denied OS permission or missing APK native plugin can prevent immediate alerts. Existing APK binary/plugin configuration was not inspected. No claim that employees received notifications is made. Final two-account receipt tests and real network quality measurements require participating devices; the interface provides an explicit self-test on the current browser.
