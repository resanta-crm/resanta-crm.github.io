# РЕСАНТА AI 360° — первый безопасный этап голосовых поручений

Дата: 24 октября 2026. Статус: **подготовлено в отдельной ветке, не внедрено в production**.

## Что подготовлено

- \`assets/140-resanta-ai360-task-drafts-preview-v1.js\`: необязательный голосовой/текстовый интерфейс без сохранения. Просмотр, выбор, изменение срока, отмена черновиков.
- \`supabase/functions/crm-ai360-task-drafts-v1/index.ts\`: отдельная будущая Edge Function, **не задеплоена**, которая читает уже существующий серверный снимок CRM и дополнительно перепроверяет клиента, исполнителя, регион, незавершённые задачи и запланированные маршруты.
- В исходниках голосового UI (134) и ленивого загрузчика (137) ветки добавлены только точки подключения модуля. **В main эти изменения не переносили.**
- \`tests/ai360-task-drafts-readonly-v1.test.cjs\`: сценарии команд и защиты.

## Безопасность и ограничения пилота

1. Только директорский аккаунт, только менеджеры с регионом \`Витебск\`, только клиенты региона \`Витебская область\`/ \`Витебск\`.
2. Читаются только проверенные данные \`clients\`, \`tasks\`, \`route_plans\`, а сведения о снижении — из существующей серверной функции \`crm_ai360_operations_snapshot_v1\`.
3. Текущий месяц не сравнивается как завершённый. Сравнение — последний закрытый месяц с аналогичным месяцем прошлого года; речь только о **связанных** продажах.
4. Если есть открытая задача, актуальный маршрут, неоднозначный клиент, неясное закрепление либо неполный ответ БД — новый черновик не предлагается. Отклонения не исправляются автоматически.
5. Возвращается не более 3 черновиков с источником, основанием, сроком, действием, ожидаемым результатом и критерием.
6. Только просмотр в памяти текущей вкладки: нет \`insert\`, \`update\`, \`delete\`, \`upsert\`, новой таблицы, записи аудио/промптов и вызовов платной LLM.
7. Голосовое «согласовать» **только отмечает черновики**. Сообщение прямо предупреждает: «НЕ согласование и НЕ создание задач».
8. По-прежнему запрещён голос на Android/WebView и на экране входа. Никакого фонового обращения к серверу без команды.

## Откат

Поскольку изменения находятся **только в отдельной ветке**, немедленный откат до выпуска — не мержить ветку. После релиза достаточно откатить точки подключения \`134\` и \`137\` на ранее зафиксированные версии / отключить Edge Function. Основные таблицы, роли, RLS, задачи, авторизация, Android, склад и Triovist не меняются.

## Следующий, ещё НЕ согласованный этап

Серверная транзакция \`draft -> revalidate -> explicit confirmation -> insert tasks + audit\` с уникальным idempotency key. Нужно отдельно спроектировать таблицу аудита, защиту от двойного подтверждения, разграничение филиалов и атомарный откат. До этого никакой записи в \`public.tasks\` голосом.
