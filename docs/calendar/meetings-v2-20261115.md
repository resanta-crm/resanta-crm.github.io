# Calendar and meeting preparation v2

Approved scope: calendar access for all active CRM employees except Nesterov (immutable ID exclusion). Personal meeting data remains owner-only. Calendar access does not grant additional financial, employee, category or client permissions. Unknown analytical roles receive a personal calendar, not network analytics or a newly enabled Lera account.

Preparation uses the calendar date/month and authenticated analytical scope. A new isolated Edge workflow reads 27 SQL aggregate sources and existing sales/operations/Triovist profile RPCs. No sampling limit is used for aggregates. Current complete card imports, task approval status, existing LPR responsibility fallback, transaction timezone and overlapping budget periods are respected. Explicit checks cover missing client fields, visit outcomes, confirmed overdue tasks, report freshness, stock anomalies, markdown review stage, stand condition, warehouse failures, current card issues, prices and parser failures. The catalogue still distinguishes aggregate metrics from all business rules being checked. Personal chats are not scanned automatically.

Existing revenue, budget, legal entity, route and other section calculation functions are unchanged. Network and branch amounts are not mixed for staff. Category accounts only read their own cards/issues/tasks/LPR metrics. Closed-month KPI gaps can be high when source freshness is confirmed; unfinished-month gaps are discussion topics, not critical failures. Stale-review tasks do not contribute to confirmed overdue priority. Source failure does not abort other sources.

Server-created preparation snapshots bind context and results to the owner; the browser cannot submit trusted figures. Lera discussions of the meeting consume these snapshots with the existing metered conversation flow. Detailed business questions retain the original scoped gateway. Snapshots older than 15 minutes are marked outdated in the discussion context. Existing greetings, history consent and generic conversation are preserved.

Meetings support confirmed creation/edit/transfer/cancellation, saved agendas, and minutes. Updates detect stale versions. A database advisory lock and overlap trigger serialize all meeting writers, including signed Lera actions. Cancelled records are excluded from both calendars and spoken agenda; cancelled slots can be reused. The calendar loads keyset pages over the displayed range and includes overnight meetings. Spoken agenda supports tomorrow, today, explicit date/range, calendar-selected day and weeks with bounded continuation. Invitations, RSVP, participant availability and automatic meeting reminder delivery remain a separately agreed follow-up; the UI states they are not active.

Navigation changes are limited to the calendar exception in existing role shells (Triovist, service, office and auditor). No unrelated navigation destination becomes available.

Validation: functional local tests for scopes, date/context invalidation, source failures, agenda persistence, cancellation, stale tasks and priorities; compatibility tests for existing Lera/actions/history/Triovist, control center, CONNECT and account access. Live SQL aggregate checks and an authenticated transaction tested owner creation, agenda update, stale-version rejection, overlap rejection, manager isolation and excluded-user rejection; all fixture writes rolled back. Local desktop/mobile layout checked with demonstration data. Physical APK devices and real invitation/reminder delivery were not tested or claimed.
