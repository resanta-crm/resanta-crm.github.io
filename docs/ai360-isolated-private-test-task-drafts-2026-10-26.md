# РЕСАНТА AI360 — изолированные тестовые голосовые поручения (26.10.2026)

## Согласованное поведение

Пока Лера тестируется, **Руднев, Шкуран, Ачинович и другие менеджеры не видят пробные поручения**. Существующая таблица `public.tasks` не используется для тестовых записей. Задачи не появляются в списках, счётчиках, уведомлениях, KPI и общих отчетах. Нет маршрутизации тестовых записей в реальные поручения.

## Серверная изоляция

1. Новая `public.ai360_voice_test_drafts_v1`: `status='test_draft'`, `approval_id`, `client_id`, менеджер, описание, срок, основания, ожидаемый результат и критерии, `created_by`.
2. RLS ON, 0 policies. REVOKE ALL у PUBLIC/anon/authenticated. Только `service_role` может SELECT и INSERT; UPDATE/DELETE/TRUNCATE у service_role отозваны. Роли менеджеров не имеют доступа ни через PostgREST, ни через RLS.
3. `crm-ai360-task-approval-v1` v2 **на сервере отключает настоящий commit**. Принимает только `validate`, `commit_test`, `list_test`. Старая команда `kind='commit'` отклоняется. `commit_test` требует точную строку «подтверждаю сохранение тестовых поручений», полный директорский JWT/role/owner guard и повторную проверку клиента, менеджера, задач и маршрутов.
4. Одна атомарная INSERT только в тестовую таблицу; идемпотентные идентификаторы зависят от `approval_id + client_id + ai360-private-test-draft-v1`. Повтор тестового сохранения не создаёт копии. Настоящих задач создано 0.
5. `list_test` возвращает последние 12 тестовых поручений только для владельца `created_by`. Менеджеры не смогут вызывать эту функцию успешно.

## Голосовой сценарий директора

- «Лера, предложи три поручения для Руднева» — черновики только в окне Леры.
- «Лера, согласую первое поручение для Руднева» — validate, без INSERT.
- **«Подтверждаю сохранение тестовых поручений»** — запись только в закрытый директорский тестовый журнал, НЕ в `tasks`.
- «Лера, покажи тестовые поручения» — чтение реально сохранённых тестов из базы, не просто показ старого ответа.
- Старая фраза «Подтверждаю создание поручений» блокируется и не создаёт рабочую задачу.

## Граница безопасности

Это тест реальной серверной записи, но **не полноценная проверка будущего производственного создания задач**. Когда пилот будет завершён, потребуется отдельное согласование на включение реального `tasks`-создания и новые интеграционные проверки. Без такого решения настоящий `commit` остаётся запрещённым на сервере.

## Проверка

До начала теста в `public.ai360_voice_test_drafts_v1` — 0, в `tasks` с `source='ai360_voice_approved'` — 0. Проверять:
1. До подтверждения обе таблицы остаются без новых тестовых/голосовых записей.
2. После тестовой фразы появляется запись только в `ai360_voice_test_drafts_v1`.
3. Роль `authenticated` не получает SELECT по таблице; `service_role` может лишь SELECT/INSERT.
4. В голосе `list_test` возвращает сохранённую запись, закрытую от менеджера.
5. Повтор с тем же `approval_id` не создаёт второго экземпляра.

## Откат

Вернуть в GitHub старый `140` и версии кэша можно, но **не возвращать прежний серверный код с реальным INSERT в `tasks` без отдельного письменного согласования**. При проблемах оставить сервер в test-only режиме или отключить тестовые сохранения. Тестовую таблицу безопасно оставить; ни она, ни её данные не участвуют в рабочих задачах.
