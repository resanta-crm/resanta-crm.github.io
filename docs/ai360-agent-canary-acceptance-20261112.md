# AI Agent 360° — проверка пилота перед подключением в CRM (12.11.2026)

## Цель
Подтвердить работу уже развёрнутого `crm-ai360-agent-v1` (Supabase v2) на реальных JWT пользователей **без изменения CRM-данных**. Статус ACTIVE, успешный CI и 401 без JWT не равны успешному авторизованному запросу.

## Два первых пилотных аккаунта
1. Директор сети: проверенная учётная запись Александра Паюшина, маршрут `crm-ai360-dialog-v4`.
2. Петровичев: проверенная существующая учётная запись «Руководство компании», маршрут `crm-ai360-director-peer-v1`. Должны совпадать ID, email, подтверждение email, role boss, access_scope standard, region «Все филиалы». Нельзя переименовывать пользователя ради приветствия или менять ему роль.

Оба должны видеть один и тот же список разрешённых *читательских* доменов (34). Это ещё не утверждение о равенстве **всех** административных возможностей CRM. Операции записи у AI Agent выключены.

## Испытания, проводимые только с собственными пользовательскими сессиями
- Не собирать, не экспортировать и не присылать JWT, refresh token, пароль или cookie, не использовать service_role как пользовательский токен.
- Получить `capabilities` из `crm-ai360-agent-v1` после реального входа в CRM — HTTP 200, соответствующая роль, персональное приветствие, доступные домены.
- Проверить по отдельности вопросы: «Что с продажами за октябрь?» / «Что с ПДЗ?» / «Какие акции без продаж?» / «Где слабые показатели менеджеров?» / «Покажи задачи» / «Сколько остатков на складе?» / «Что с Триовистом?» — сверить цифры, дату импорта, методологию и отображение неполных выборок с действующими экранами CRM.
- Продолжение «А у Руднева?» и смена темы «А что по 21vek?» должны корректно переопределять область разговора, без смешения менеджера, клиента или валюты.
- Петровичев не должен получать отказ owner_only, но его ответы должны использовать подтверждённый источник. Если ответ без подтверждённых фактов, тест не пройден.
- Неизвестный/отключённый пользователь: отказ 403. Анонимный POST: отказ 401. Запросы create/update/delete/approve/send: отказ или черновик без записи, в соответствии с доступной фазой.
- Имитировать истёкшую сессию, смену пользователя, двойное нажатие, прерывистую сеть. Не допускаются «подставные» результаты или повторное использование чужого контекста.
- Замерить время ответа, нагрузку, бюджет GPT, число повторных запросов. Возвраты ошибок должны быть понятны и не раскрывать детали backend.

## Условия подключения в браузере
1. После успешного авторизованного теста для обоих директоров добавить в браузер *опциональный* флаг AI Agent, не подменяя существующую Леру.
2. Не добавлять второй микрофон, второй voice loop или автоматическую загрузку всего CRM. Начальный режим — **только текстовый read-only диалог** после явного нажатия.
3. Протестировать на владельце и Петровичеве. Затем допустить шесть ранее разрешённых работников: только собственные разрешённые домены.
4. Отдельно проверить голос TTS/STT, Android WebView и USB INMO AIR3. Ничего не объявлять работающим на очках до аппаратного подтверждения.
5. Если меняются роли, backend-каталог или меню в соседнем чате «Улучшения CRM», повторить CI и сверку перед слиянием PR №286.

## Отсечка
Не сливать PR №286 в main и не включать для всех до положительного теста JWT+данные+роли. Нет доступного способа проверить **подписанный пользовательский диалог** без входа самого пользователя через разрешённый интерфейс; это не следует заменять ролью service_role или незаметным получением токенов.
