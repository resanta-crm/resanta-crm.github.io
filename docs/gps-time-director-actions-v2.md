# GPS «Контроль времени» v23.7.8 — действия ДФ

## Для чего
Директор быстро выясняет, какая GPS-остановка заслуживает внимания и нужны ли действия по будущему маршруту или поручению. Не дисциплинарный рейтинг; отметка «техническая» не означает отсутствие посещения.

## Пользовательский сценарий
1. В CRM: GPS-контроль → «Руководитель» → «Контроль времени».
2. Выбрать период до 31 дня, менеджера и порог, нажать «Проверить время».
3. **Нажать на любую из шести верхних метрик**: все дни, надёжные дни, ненадёжные дни с конкретной причиной, остановки к разбору, минуты к разбору, повторы. Внизу открывается нужная детализация.
4. Нажать на строку дня/недели/месяца → отфильтровать список соответствующих остановок (с учётом менеджера). Карта открывается по конкретному дню.
5. Для конкретной остановки выбрать **«✦ ИИ-разбор»**: сервер проверяет факты, вызывает ИИ по запросу, возвращает одну короткую рекомендацию и ограничения. Не изменяет маршруты, GPS или визиты.
6. По решению ДФ: открыть **ручной редактор будущих маршрутов**, **поручить менеджеру** (можно другому; конкретный срок, подтверждение, антидубль) либо **«Не требует действий»** с пояснением. Последний выбор архивирует остановку из рабочей очереди и вычитает минуты из цифры «К разбору». Историю можно снова увидеть по кнопке «Показать разобранные».
7. Поручение менеджеру формулируется нейтрально (результаты поездки, возможная корректировка будущих маршрутов); детали внутреннего GPS-анализа и метки подмены не передаются менеджеру.

## Исправление реальной ошибки
Раньше повторы определялись попаданием координат в одну округлённую географическую ячейку. Два близких места в соседних ячейках пропадали. Теперь RPC сопоставляет координаты проверенных остановок того же менеджера **по геодезическому расстоянию ≤200 м в разные дни** (эвристика близости, не доказательство совпадения адреса). Проверка 1–20.10.2026, порог 60 мин: раньше 0, теперь 4 остановки в повторных парах.

## Безопасность и расходы ИИ
- Изолированный Edge Function `crm-gps-stop-ai-v1`, JWT и директорское разрешение (две учётные записи).
- База повторно проверяет выбранную остановку через защищённую RPC, прежде чем данные попадут в запрос к ИИ.
- В запрос к модели идут только продолжительность/точность/даты остановки, агрегированные минуты и краткие факты визитов. **Без координат и сырых GPS-точек.**
- `gpt-5-mini`, лимит 8 новых генераций на руководителя за 24 часа; совпадающие доказательства возвращаются из 6-часового закрытого серверного кэша.
- При недоступности ИИ карта и обычная аналитика работают независимо.
- Модель не уполномочена автоматически удалять визиты, переносить клиентов между менеджерами или корректировать маршрут.
- Кэш доступен серверному коду через service role, RLS и запрет клиентского доступа.
- Разбор выполняется по кнопке; без фоновых запросов и затрат при открытии CRM.

## Не входит
- Расчёт доказанного времени бездействия, штрафов/нарушений и личных выводов о сотрудниках.
- Автоматическое исключение завершённой ТТ из отчёта или изменение доказательств посещений.
- Полная дорожная оптимизация без внешней дорожной информации.
- Глобальный ИИ-брифинг по CRM.

## Проверить после публикации
- Выбрать 01–20.10, порог 60. Увидеть прежние 31 GPS-день, 13 надёжных, 18 недостаточных, 10 кандидатов, 977,2 мин до обработки, **4 повторные остановки**.
- Нажать на каждую метрику: список/причина/нужный менеджер; открыть Руднев 20.10 и его остановку 99,2 мин.
- ИИ-разбор: ответ краткий, достоверный, с ограничениями; ошибка ИИ не мешает карте.
- Нейтрально поручить другому менеджеру до выбранной даты и повторить — нет дубля одной открытой задачи для менеджера+остановки.
- Отметить «Не требует действий» с обоснованием; цифры «к разбору» уменьшаются, история не теряется.
- Проверить вход под обычным менеджером — кнопок/ИИ-сводки быть не должно.
- Обязательно выполнить браузерный smoke test под учётной записью директора перед признанием UI полностью проверенным.
