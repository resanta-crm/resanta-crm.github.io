# РЕСАНТА AI360 · голосовое согласование задач (26.10.2026)

## Рабочий сценарий

1. Директор говорит «Лера, предложи три поручения для Руднева». Старый модуль `crm-ai360-task-drafts-v1` даёт до трёх черновиков, **без записи**.
2. Директор меняет дату/текст и выбирает один или несколько номеров.
3. «Согласовать первое и третье» или «Согласовать выбранные» — отдельная Edge Function `crm-ai360-task-approval-v1` запускает **только** `validate`, повторно проверяет директора, менеджера филиала Витебск, клиентское закрепление, актуальность сигналов, существующие открытые задачи и будущие маршруты, после чего озвучивает список. **На этом шаге INSERT нет.**
4. Фраза **ровно** «Подтверждаю создание поручений» отправляет `commit`; сервер повторно выполняет все проверки и только тогда выполняет одну транзакционную многострочную INSERT в `public.tasks` (не более трёх). После успеха Лера показывает число созданных поручений. Обычное «да», «согласен», «утверждаю» не создаёт ничего.
5. «Отмена создания», изменение срока или текста, удаление черновика сбрасывают подготовленное подтверждение.

## Защита данных

- Только директор, фиксированный user ID и проверенные профиль/роль; `verify_jwt=true`; origin allowlist.
- Все клиенты и менеджеры повторно проверяются на сервере. Задачи создаются только у закреплённого менеджера с реальным `manager_id`, `client_id`, `due_date`, `title`, `text`, `basis`, `expected_result`, `criteria`, `priority`, `review_status=approved`.
- Не более 3 задач за одно подтверждение; только срок от завтра до 90 дней; текст 8–500 символов.
- Одно `insert(rows)` через PostgREST — атомарно. Стабильный UUID из `approval_id + client_id` предотвращает повторную вставку после сетевого сбоя, даже если прежняя задача уже закрыта.
- Миграция Supabase `ai360_voice_approved_open_client_uniqueness_v1` создала частичный UNIQUE-индекс `tasks_ai360_voice_open_client_unique_v1` только для `source='ai360_voice_approved'` и открытых задач. Он защищает от одновременного создания двух голосовых задач на одного клиента через разные инстансы Edge. Существующих записей этого source до изменения — 0.
- Нет новых таблиц, удаления/изменения старых задач, изменения RLS/auth, изменений Android.
- Во всех случаях ошибки/неясного ответа запрещён автоматический повтор `commit`. Директор может повторно произнести полную фразу; идемпотентный UUID и серверная проверка блокируют дубли.

## Релиз и тестирование

- Серверный endpoint `crm-ai360-task-approval-v1` version 1, `verify_jwt=true`. Модуль черновиков прежний, не требует изменения.
- Подключён новый UI-файл `140-resanta-ai360-task-drafts-preview-v1.js?v=3` директорским lazy loader v17, Android исключён.
- В тестовом V8 окружении: существующие голосовые/черновые тесты плюс `ai360-voice-final-approval-20261026.test.cjs` и `ai360-task-approval-backend-v1.test.cjs`. Смоделированы validate без записи, точная финальная команда, идемпотентность повторного `commit`, отсутствие прав, конфликты и отмена.
- **Ограничение:** реальный end-to-end с директорским JWT и создание настоящих задач в пользовательской CRM этим тестированием не выполнялись. До такого теста не утверждать, что процесс полностью испытан на данных пользователя.

## Проверить в Яндекс Браузере

Открыть CRM, Ctrl+F5, включить Леру. Сказать «Лера, предложи три поручения для Руднева», затем «Согласовать первое». Убедиться, что Лера **только перечислила** готовое к записи и запрашивает точную финальную фразу. До реального подтверждения никаких новых задач быть не должно. После явной фразы «Подтверждаю создание поручений» проверить появление одной задачи в CRM в разделе поручений нужного менеджера и отсутствие дубля после второго такого же текста.

## Откат

Первый шаг при неисправности — вернуть версии `assets/140`, `assets/137` и `index.html` в main к состоянию до этого релиза (ранее в основной ветке это было `140?v=2`, `137?v=16`). Это отключит возможность создавать голосовые задачи, но не сломает голосового помощника или черновики. Для полного отключения также можно снять функцию `crm-ai360-task-approval-v1`. Частичный индекс безопасно оставить: он не влияет на остальные sources. Откат не удаляет уже созданные поручения.
