# РЕСАНТА AI360 — исправление маршрутизации голосовых согласований и статусов задач, 26 октября 2026

## Причины по скриншоту директора

Распознанная фраза «Согласую первое поручение для Руднева» не подходила под старый `PREPARE` (не учитывал форму «согласую»). Если активных черновиков нет, модуль возвращал `false`; после этого `assets/134` передавал запрос аналитику продаж и задач (`assets/138`), где Лера вместо согласования рассказывала о 246 открытых / 191 с просроченным сроком. Аналогично фраза с именем Руднева могла применяться к открытым черновикам Шкурана из-за отсутствия проверки фамилии на клиенте.

Дополнительная проблема — `stale_review` и `approved` выводились в одну группу просроченных по дате без объяснения статуса. Проверка базы на 26.10.2026: **246** открытых у Руднева, **191** с прошедшим сроком (из них **174** `stale_review`, **17** `approved`), **2** открытые без срока. 174 «требуют пересмотра», нельзя автоматически считать подтверждённым неисполнением.

## Реализовано

1. `assets/140-resanta-ai360-task-drafts-preview-v1.js`: явное выделение **намерения подготовки согласования** для «согласую», «согласовать», «утверждаю», «одобряю», «согласен на первое» и соответствующих вариантов. Оно **никогда** не заменяет точную финальную фразу «Подтверждаю создание поручений».
2. Если активных черновиков нет, Лера сообщает «Сначала попроси предложить поручения» вместо перехода в общую аналитику.
3. Если в команде назван другой менеджер или фамилия неизвестна/неоднозначна, подготовка блокируется; никакой `validate` / `commit` не запускается. Директор должен сначала запросить предложения нужного менеджера.
4. `assets/134-resanta-voice-ai360-pilot-v1.js`: защитный маршрутизатор перехватывает намерение согласования и при отсутствующем/сломавшемся sidecar не допускает перехода к sales LLM.
5. `supabase/functions/crm-ai360-director-v1/index.ts`: при задачах конкретного менеджера — только чтение, пять параллельных `count:exact, head:true` запросов: все открытые, просроченные по дате, все `stale_review`, просроченные `stale_review`, просроченные `approved`. Если источник неполон/противоречив — ответ не выдумывается.
6. `intent-router.mjs`: разделение статусов передаётся в LLM evidence и безопасный fallback. Прямой подсчёт задач теперь даёт проверенное число по каждой категории; «просроченные задачи» не трактуются как долг дебитора.

## Безопасность

- Отдельная функция `crm-ai360-task-approval-v1` и сценарий точного подтверждения не изменялись.
- Текущие задачи, маршруты, клиенты, GPS, авторизация, RLS, схемы и Android не изменяются.
- Ни одно поручение автоматически не создаётся. Все голосовые подтверждения по-прежнему требуют двух отдельных действий.
- Применяются прежние защиты Supabase JWT, ролей, закрепления клиента, уникальности и запрета повторной записи.
- Версии кэша: голосовой модуль `134?v=14`, согласование `140?v=4`, lazy loader `137?v=18`.

## Тестирование и границы проверки

9 наборов файловых/VM-тестов, включая:
- новые `ai360-approval-routing-manager-guard-20261026.test.cjs` и `ai360-task-review-status-breakdown-20261026.test.cjs`,
- имеющиеся тесты сессии, голоса, интерфейса, черновиков, предварительного и окончательного подтверждения, серверной идемпотентности.

Эти тесты не являются полноценной проверкой в реальном браузере под директорской авторизацией. При публикации следует проверить точный сценарий пользователя и убедиться, что никакие задачи не созданы без отдельной команды.

## Ручная проверка

1. Открыть `resanta-crm.by` и обновить Ctrl+F5.
2. Без активных черновиков сказать «Согласую первое поручение для Руднева» — Лера должна попросить сначала предложить поручения, не выполнять анализ задач.
3. Подготовить предложения для Шкурана, затем сказать «Согласовать первое поручение для Руднева» — явный отказ из-за несовпадения менеджера.
4. Подготовить для Руднева, сказать «Согласую первое поручение для Руднева» — **только** серверная проверка `validate`; финальной записи нет.
5. Отдельно спросить «Сколько просроченных задач у Руднева?» — показываются согласованные и требующие пересмотра, а не обвинительный единый вывод.
6. Для реального создания по-прежнему требуется буквальная фраза «Подтверждаю создание поручений». Не произносить её при диагностическом тесте.

## Откат

Вернуть `134`, `140`, `137` и `index.html` к предыдущему коммиту main, отдельно повторно развернуть `crm-ai360-director-v1` v14 из `index.ts` и `intent-router.mjs` без изменения токенов/флагов JWT. Существующие данные и `crm-ai360-task-approval-v1` не откатываются.
