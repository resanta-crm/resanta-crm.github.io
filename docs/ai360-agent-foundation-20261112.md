# РЕСАНТА AI Agent 360° — безопасный фундамент, 12.11.2026

## Что реализовано в отдельной ветке
- Новая единая точка входа Edge Function crm-ai360-agent-v1: только POST с проверенным пользовательским JWT.
- Для сетевого директора направляет запрос в существующий crm-ai360-dialog-v4 с 34 контролируемыми областями чтения.
- Для ранее допущенных сотрудников направляет запрос в crm-ai360-staff-dialog-v1 с ИХ JWT. Ограничения ролей, филиалов, клиентов и товарных категорий сохраняются.
- Для всех платформ — один добровольно подключаемый JavaScript-адаптер assets/210-resanta-agent360-single-entry-v1.js с методами ask, capabilities, reset; без фоновых запросов и отдельного микрофона.
- Реестр UI-навигации: 23 пункта основного меню плюс вложенные разделы Триовиста, склад, ТСД, оплату, инфографику и др. Для каждой поверхности указаны существующие backend-домены. Покрытие отмечается как partial или not_connected_or_not_authorized; никогда как полный охват без доказательств.
- Регрессионные тесты на соответствие меню, запрет расширения прав, запрет записи, отсутствие eager-запросов, смену пользователя и перекрытие запросов.

## Чего эта ветка НЕ делает
- Не изменяет index.html, глобальную навигацию, работающий UI, GPS, акции, финансовые расчёты, 1С или схему Supabase.
- Не разворачивает Edge Function в production и не переключает существующую Леру.
- Не предоставляет новых непроверенных SQL/RPC и не даёт менеджерам доступ к директорским данным.
- Не создаёт встречи, задачи, не отправляет сообщения и не подтверждает платежи. Такие команды пока могут породить только рекомендации существующего диалога; любые операции create/update/delete/approve/send на новом шлюзе запрещены.
- Не внедряет голосовое пробуждение AIR3 и не устраняет зависания входа APK без аппаратной проверки.
- Не делает из ограниченных выборок полностью проверенную аналитику каждого SKU и всех скрытых вкладок.

## Контракт для будущих клиентов
Запрос с текущим JWT через существующий Supabase SDK:
- db.functions.invoke('crm-ai360-agent-v1', {body:{action:'capabilities'}}) — разрешённые сервером домены и карта частичного покрытия;
- db.functions.invoke('crm-ai360-agent-v1', {body:{action:'ask',question:'Почему упали продажи?',history:[],memory:{}}}) — единый разговорный запрос.

В новой ветке доступен необязательный адаптер с методами:
- window.crmAgent360SingleEntryV1.ask(question)
- window.crmAgent360SingleEntryV1.capabilities()
- window.crmAgent360SingleEntryV1.reset()

Адаптер нужно явно загрузить после штатного входа. Он не обращается в сеть при загрузке и не включает микрофон. Сервер не доверяет роли, домену или пользователю из payload; JWT и права повторно проверяются в существующих серверных функциях. Поле answer_verified сохраняется без повышения уровня достоверности.

## Условия до публикации
1. Зелёные новые и существующие CI тесты, особенно auth, маршруты, акции, Триовист, менеджеры и Android voice gates.
2. Повторная проверка после текущей доработки «Улучшения CRM»: не поменялись ли меню и роли; новые пункты требуют явной регистрации.
3. Тест Edge с директором сети, ДФ, МПП, категорийщиком и запрещённой ролью; отсутствие чужих данных.
4. Проверка лимитов OpenAI, отчётов 1С, обрыва сети, обновления JWT, времени ответа и отсутствия дублирующих запросов.
5. Отдельная публикация новой функции без замены v4/staff; затем канареечный флаг для пользователей.
6. Поэтапное добавление подтверждённых предметных инструментов, безопасных действий с подтверждением и тестов браузера, Android, INMO AIR3.

## Принцип развития
Каждый новый раздел регистрирует навигацию, источники фактов и методологию, серверные права, разрешённые операции и автоматические тесты. Само появление UI-раздела не выдаёт ИИ право на данные или запись. Реестр отслеживает пробелы покрытия и становится основой для единого ИИ-брифинга.
