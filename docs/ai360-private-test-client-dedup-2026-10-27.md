# РЕСАНТА AI360 — защита от повторных тестовых поручений, 27 октября 2026

## Реальные наблюдения
- Пользователь прислал OBS `2026-10-27 08-02-32.mov`, 87,63 с. Проверка всех 2629 кадров через ffmpeg `blackdetect`: вся запись чёрная. Причина — OBS «Источники» пустые на предыдущем скриншоте. Аудиодорожка присутствует. По чёрному видео невозможно уверенно судить о визуальных ошибках CRM.
- Supabase показал **два** `test_draft` для **одного client_id** в запусках с разными approval_id. Первый 27.10.2026 07:57:56 Минск, второй 08:03:28. Оба имеют одинаковое содержание и срок, но действительно сохранены в отдельной тестовой таблице. `tasks` с `source='ai360_voice_approved'`: ноль.
- Причина: прежняя идемпотентность по `approval_id + client_id` защищала от повтора одной команды, но не от второго независимого тестового запуска для того же клиента.

## Реализованное исправление
1. PostgreSQL trigger `ai360_private_test_unique_client_guard_v1` под `SECURITY INVOKER` с транзакционным advisory-lock на директора и клиента и проверкой существующего test_draft. Он предотвращает параллельные и последовательные повторные тестовые сохранения с другими approval_id, **не удаляя исторические 2 записи**.
2. Edge `crm-ai360-task-approval-v1` v3: дополнительно сверяет существующие тестовые записи клиента, отдаёт 409 `test_client_already_saved` с нулём вставок. Старая блокировка реального `kind='commit'` и все проверки директора/менеджера сохранены.
3. Edge `crm-ai360-task-drafts-v1` v4: исключает клиентов, по которым у директора уже есть сохранённый тестовый черновик, из новых предложений. На недоступном хранилище ошибку не скрывает.
4. Frontend `assets/140` v6: вместо технического кода ошибки объясняет, что тест для клиента уже сохранён, и предлагает запросить других клиентов; lazy loader v21.
5. Есть изолированный тест `tests/ai360-private-test-dedup-20261027.test.cjs`. Поведенческие существующие тесты голоса, предварительного и окончательного согласования и preview должны оставаться зелёными.

## Выполненные проверки
- Триггер реально установлен в Supabase; пробная повторная INSERT внутри защищённой SQL операции отклонена уникальным исключением, новых строк не появилось.
- VM-тесты для backend, draft UI, одного запроса/превью, стадий согласования и нового межсеансового запрета прошли. Эти проверки не заменяют реальную пользовательскую проверку на Mac.
- Тестовое хранилище RLS ON, 0 policies; нет grants у authenticated. Изменений прав сотрудников и `public.tasks` нет.

## Откат
Откатить Edge функции к версиям v2/v3 и frontend к sidecar v5 (lazy v20) можно, но БД trigger **без отдельного согласования не удалять**: его наличие безопасно, он предотвращает дубли. Реальный `commit` ни при каком откате не включать без отдельного одобрения.
