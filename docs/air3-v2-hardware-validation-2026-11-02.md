# RESANTA AI360 · INMO AIR3 — проверка реальных очков, 02.11.2026

**Источник:** пошаговые пользовательские испытания на собственном INMO AIR3 c MacBook Neo, 2 ноября 2026 года. Показания проверены по снимкам терминала, экрану приложения и сообщениям владельца. Это `hardware validation`, **не** подтверждение готовности полноценной Леры или CRM.

## Подтверждено вживую

- macOS разрешила USB-аксессуар `INMO PARROT-QRD`.
- `adb devices` показала одно авторизованное Android-устройство в состоянии `device`.
- `adb install -r /Users/aleksand/Downloads/resanta-air3-test.apk` вернула **Success**.
- `adb shell am start -n by.resanta.air3probe/.MainActivity` успешно запустила приложение; в очках отображены три тестовые кнопки.
- `adb exec-out screencap -p` создал реальный скриншот экрана.
- `scrcpy 4.1` на Apple Silicon отобразила **живой экран**, а нажатие кнопки мышью на MacBook изменило экранное сообщение на очках; input injection подтверждён.
- Данные тестовой APK: Android **14 / API 34**; WebView **137.0.7151.115**; `MediaProjection API: есть`.
- **Локальный (on-device) SpeechRecognizer отсутствует** по данным нашей APK. Это не доказывает неисправность микрофона или невозможность облачного STT.
- Доступ к CRM **не запрашивался**, аудио не передавалось в нашу CRM, трансляция через MediaProjection **не включена**.
- Статус официального обновления прошивки не подтверждён; обновление пользователь отложил.

## Задача следующего этапа

1. Реальная аппаратная запись голоса `MediaRecorder`: в отдельной ветке добавлена **тестовая версия 0.2 с кнопкой краткой записи и локального воспроизведения**. После зарядки проверяем на конкретных очках, не называем эту функцию проверенной до испытания.
2. Не заводить отдельную разговорную Леру. Подключить те же действующие авторизованные AI360/STT/TTS backend paths и каталог разделов, что доступны директору, с серверной проверкой роли, прав и журнала.
3. Вместо 30-минутного браузерного пилота разработать и отдельно проверить защищённый **одночасовой device-bound session**: absolute TTL 3600 секунд, idle 600 секунд от пользовательских действий, remote revoke, только RAM token, никаких паролей/JWT или приватных данных в SharedPreferences. Часовой сеанс **ещё не готов**.
4. Презентация для зала — отдельный разрешённый display viewer, **не** полное зеркалирование рабочего стола MacBook и не показ всей CRM.
5. Показатели на сцене: заранее согласованная презентация + несколько разрешённых демонстрационных разделов из CRM; переключение командами Леры; без утечки конфиденциальных данных/уведомлений.
6. Продакшен и APK полевых менеджеров не менять; физическую совместимость прошивки с системным wake-word `Привет, IMO` нельзя обещать.

## Безопасно завершить сеанс и проверить после зарядки

1. На MacBook закрыть окно scrcpy, остановить активный терминальный процесс через `Control+C` при необходимости.
2. Отключить USB-C, выключить очки штатным способом, зарядить от обычного адаптера.
3. Переустановка APK **не требуется**: `by.resanta.air3probe` зарегистрирована Android Package Manager и сохраняется после перезагрузки, если устройство не выполнит сброс/удаление.
4. После зарядки открыть приложение через меню очков (при доступном launcher), либо подтвердить пакет через `adb shell pm list packages by.resanta.air3probe` и снова запустить `adb shell am start -n by.resanta.air3probe/.MainActivity`. Связь scrcpy/ADB не переживает выключение или отключение USB и запускается заново.
5. Общие очки: по окончании работы выключить `USB debugging` в Developer Options, снять доверие к незнакомым компьютерам/отозвать ADB debugging authorizations, не сохранять личные учётные записи. При следующей разработке USB debugging включить повторно осознанно.
