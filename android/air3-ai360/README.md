# РЕСАНТА AI 360° для INMO AIR3 · первая работающая голосовая сборка

Статус: **pilot / hardware acceptance pending**. Дата 3 ноября 2026 г.
Согласовано владельцем на переход от диагностического `air3.html` к реальной нативной Лере.
Репозиторий: PR #157, отдельная ветка; production CRM `index.html` и APK менеджеров не изменены.

## Что реализовано и проверено автоматикой

- Android-приложение `by.resanta.air3` (отдельно от старого `by.resanta.air3probe`).
- Живая запись 7-секундного вопроса в `MediaRecorder` (после отдельного нажатия), временный локальный файл удаляется.
- OpenAI STT (`gpt-transcribe`) c общим лимитом `crm_voice_claim_v1` / `crm_ai360_stt_claim_v2`.
- Общая логика Lera AI360 v4: `crm-ai360-dialog-v4/core.mjs`, справочник разрешённых `catalog.mjs`, контекст и `guardVoicePair`, бюджет `crm_ai360_core_claim_v2` / `crm_ai360_core_finish_v2`.
- Yandex SpeechKit `lera` c общим бюджетом, передача PCM WAV обратно на очки и локальное воспроизведение в динамиках.
- Реальные read-only запросы к CRM в 20 наиболее значимых разделах, без передачи JWT владельца в Android-приложение.
- Существующая страница владельца `https://resanta-crm.by/air3-control.html` выдаёт 6-значный код, владелец подтверждает заявку в своём браузере. Обе стороны работают с существующей парой таблиц (RLS включён).
- Отдельный endpoint `crm-ai360-air3-v2` развёрнут: session TTL **3600 с**, idle TTL **600 с** (heartbeat не продлевает доступ), сохранён мгновенный revoke с Mac.
- Токен живёт исключительно в RAM процесса Android, `allowBackup=false`, `usesCleartextTraffic=false`; ни пароль CRM, ни Supabase JWT, ни refresh токен, ни service role не сохраняются.
- GitHub Actions проверил сборку APK + Edge module graph + security boundary. Негативный HTTP smoke (нет токена) → **401 session_required**.

## Реальный тест на очках — ещё обязателен

Нельзя считать реализацию подтверждённой, пока в физических INMO AIR3 не проверены:
- запись 7-секундной речи через микрофон; разрешение Android на микрофон;
- запрос к OpenAI STT и текст распознавания;
- реальная CRM-аналитика с корректным месяцем и role scope;
- синтез речи Яндекс Леры и воспроизведение WAV в динамиках INMO;
- 10+ минут работы без обрыва;
- таймер 60 минут и неактивность 10 минут, отзыв через Mac, отсутствие сохранённого токена после закрытия.

## Подключение без почты на очках

1. С MacBook через USB-C, из папки `platform-tools`: `./adb devices`.
2. Скачанный здесь APK `resanta-air3-lera-v1.apk` установить одной командой `./adb install -r ~/Downloads/resanta-air3-lera-v1.apk` (путь уточнить по фактическому расположению).
3. Запуск с Mac: `./adb shell am start -n by.resanta.air3/.MainActivity`.
4. На MacBook войти в CRM и открыть `https://resanta-crm.by/air3-control.html` → `Создать код`.
5. Через scrcpy ввести шестизначный код в приложении очков → `Подключить очки по коду`.
6. На MacBook в контроллере нажать `Разрешить вход`; в очках `Проверить подтверждение владельца`.
7. В очках нажать `🎙 Говорить с Лерой` и произнести `Лера, покажи продажи`; ответ должен звучать в очках, а не в Mac. Затем открыть другие разделы или задать аналитический вопрос.
8. После завершения нажать `Завершить работу` и с Mac проверить отзыв заявки. Не оставлять общие очки авторизованными.

## Не реализовано в этой первой голосовой версии

- Системная wake-фраза `Привет, IMO` для стороннего приложения; `Привет, Ресанта` без активации микрофона.
- Бесконечный hands-free listening: на каждую голосовую реплику пока нужен явный запуск записи, чтобы не расходовать бюджет на тишину и не вести скрытую запись на общем устройстве.
- Полная пользовательская оболочка всех разделов CRM/автоматическая запись поручений. Подключены основные read-only аналитические домены, некоторые (например, клиентская детализация SKU) требуют отдельной адаптации.
- Режим конференции с голосовым переключением презентации для большого экрана. Отдельная задача безопасности и UX.
- Стабильный release APK signing key: GitHub debug APK подписана временным ключом; для долговременных обновлений без удаления приложения нужен постоянный ключ подписи вне публичного репозитория.

**Rollback:** новый endpoint можно отключить независимо; существующие v1 и рабочие AI360/CRM не трогаются.
